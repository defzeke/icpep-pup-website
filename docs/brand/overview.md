# Brand Overview

Source: deck page `02` (*Vision / Tone*).

## Vision

> To establish a definitive, high-precision visual identity that embodies the true
> duality of Computer Engineering—seamlessly integrating physical hardware architecture
> with structured software logic.

The deck labels this block both **Vision** and **Tone** and repeats the same statement
verbatim under each label. Read that as intent: the org's *vision* and its *voice* are the
same idea — precision, integration, no division between hardware and software.

## The duality, in practice

The whole identity hangs on one tension: **physical hardware ↔ structured software**.
Every visual decision in the deck resolves back to it.

| Hardware side | Software side |
| --- | --- |
| Isometric blocks, layered dies | PCB bus traces, solder nodes |
| Deep obsidian bases, solid mass | Glowing apertures, emitted light |
| CAD blueprint precision | Terminal layouts, code modularity |
| `#7F0525` Maroon, `#4F0212` Deep Maroon | `#F45A0C` Bright Orange, `#FB7D14` Light Orange |

Use this table when you're stuck on a design decision: ask which side of the duality the
element represents, and pull the colour, texture and geometry from that column.

## Audience

The deck is addressed to an internal audience — the first page reads *"For graphics team"*.
That has a practical consequence: the guidelines assume a designer who will apply them, not
a general reader. This documentation set exists to extend the same system to the
**web** team, where the audience is different again.

| Audience | What they need |
| --- | --- |
| Graphics team | Source of truth for social and print output |
| Web team | Tokens, component rules, and asset paths (this doc set) |
| Members / public | A site that looks deliberate, coherent and current |

## Positioning and season

The logo lockup carries an academic-year chip reading **`26-27`** — i.e. AY 2026–2027.
Treat the season as part of the identity: a new academic year means a new chip, and the
logo asset is versioned with it. See [logos.md](logos.md) for the variant inventory.

## Tone of voice

The deck supplies no copy guidelines, but its own writing is a usable sample. Observed
conventions throughout the deck:

- **Declarative, not chatty.** "The visual theme revolves around…", not "We think…"
- **Compound-technical nouns.** "Isometric Geometry", "Algorithmic", "Integrated
  Engineering Blueprint".
- **Em-dashes carrying a definition**, e.g. "…structured software logic into a unified,
  high-performance visual systems."
- **No emoji, no exclamation marks, no first-person warmth.**

Adopt this register for site copy: confident, technical, restrained. It is a
*derived* observation, not a stated rule — flag it if you disagree.
